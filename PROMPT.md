# Original Tutorial Prompt

This is the prompt used to seed the XUnit tutorial in this repo. Keep it here as a reference; modify it freely for future refreshers or new variations of the tutorial.

---

I want to learn XUnit. You are a senior software developer. You have expertise in both NUnit and XUnit. I am a developer. I have expertise in NUnit but limited familiarity with XUnit. I will be using JetBrains Rider as my IDE with the IntelliJ-style keymap (not the Visual Studio keymap), so include Rider-specific guidance (test runner UI, gutter icons, navigation, debugging) and IntelliJ-style shortcuts where it materially helps; do not turn the tutorial into a Rider manual. Create a tutorial for me to gain basic to advanced knowledge of XUnit. For the "subject," choose a domain that is generally familiar to people but complicated enough to exercise XUnit features without introducing tests just to demonstrate a feature. Create a plan for this tutorial. Remember this plan so that we can walk through it together, but also write this plan to a file so we have a record of what I have learned. The plan need not be perfect; I suspect I will have questions or will want to pursue other aspects of XUnit that neither you nor I think of to begin with. Additionally, save this prompt in a file so that if I need a refresher at some future point, I can start with this prompt (although I may also modify it).

---

## Refresher tips

When restarting from this prompt:

- Mention which sections of `TUTORIAL_PLAN.md` you have already completed so the tutorial picks up where you left off.
- If you want to swap the subject domain (Account Ledger), say so up front; otherwise the tutorial assumes that domain.
- Tell the AI whether you want a Socratic walkthrough (it asks you to predict behavior first) or a "show me the code, then explain" cadence.
- If your XUnit knowledge has grown since first running this, mention what feels stale so the tutorial can skip or compress those sections.
- If you've switched IDEs (e.g. away from Rider to VS or VS Code), say so — the Rider-specific notes will need to be retargeted.
- If you've switched Rider keymaps (IntelliJ ↔ Visual Studio), say so — the keyboard shortcuts in the plan will be wrong otherwise.
